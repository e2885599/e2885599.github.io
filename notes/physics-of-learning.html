為什麼主管要懂「學習的物理學」

你不需要會寫神經網路，但你需要一套判斷「這筆 AI 預算該不該花」的框架。市面上的說法常兩極：一端是「上大模型就對了，越大越聰明」；另一端是「AI 都是鏟雪車，別浪費錢」。兩端都太粗，簽下去很容易變成冤枉錢。

物理學家 Matthieu Wyart 的價值在於：他不用信仰說話，而是把這些現象變成可計算、可預測、可被數據打臉的模型。本筆記把他的論點翻成主管語言——重點不是「AI 多神」，而是三件事：①它什麼時候貴得有道理；②什麼時候只是貴；③你手上的問題到底落在哪一段。

主管一句話帶走

AI 的「聰明」不是均勻分佈的。同樣砸一筆錢，落在「已過相變門檻」的任務上值回票價，落在「還在卡住區」的任務上只是把錢燒成熱。關鍵是先判斷你的問題屬於哪一類，再決定預算形狀。

一、維度詛咒：為什麼資料永遠不夠，又為什麼其實夠

先講一個直覺陷阱。一張圖有 D 個像素、一句話有 D 個詞，那「所有可能的輸入」數量會隨維度指數爆炸（約 L^D）。白話說：就算你給模型一兆筆資料，攤在這個超巨大空間裡，每兩筆之間還是隔得老遠。如果資料是「均勻亂撒」的，數學上可證：模型根本無法外推，你需要比全宇宙原子還多的資料才夠——這叫維度詛咒。

那為什麼現實中的 AI 還是學得動？因為真實資料不是亂撒的，是有階層結構的。就像一張「街道」照片：底層是幾百萬個像素（邊、色塊），往上聚成「鼻子、眼睛、車子」，再往上聚成「一張臉、一條街」。深層網路厲害的地方在於，它會自動發明這些「粗粒化變數」（用概念取代像素），把原本指數級的難題壓成多項式級——可處理了。

概念來自 Wyart「街道」類比：無數行人/汽車/人行道配置，群聚成一個單一「街道」概念，模型不必逐像素記憶。
可證偽聲稱 A：只要數據由階層化生成過程產生，深網所需樣本數是維度 D 的多項式（而非指數）；淺網或傳統核方法在同等任務上仍近似指數需求。
主管解讀

「資料不夠」通常是假議題。真正的問題不是資料量，而是你的資料有沒有結構、模型架構能不能抓到結構。與其無腦買更多資料，先問「這問題本質上有沒有可壓縮的階層」。

二、雙重下降＝堵塞相變：模型不是越大越好，是「過了門檻才通」

訓練模型，本質是讓「預測誤差」當成一個能量景觀，模型沿著它往下滾（梯度下降）。Wyart 發現：這座景觀跟「沙堆、顆粒物」的能量景觀結構一模一樣。

  • 參數不夠（欠參數）：景觀粗糙、到處是局部坑洞（亞穩態）。每次重訓都卡在不同地方——像把球丟進多峰山區，落點隨機，表現不穩。
  • 參數夠多（過參數）：景觀突然出現很多平坦山谷，能量趨近零。系統「暢通」，任何起點都能流到好解。

從「卡住」到「暢通」的轉折，正是物理的堵塞相變（jamming transition）。業界後來獨立發現的「雙重下降」峰值（先降、升、再降），在物理學家眼裡就是這個相變。重點是：在門檻之前加參數，往往更貴又更爛；過了門檻之後，才進入「便宜又穩」的收斂區。

圖 2 · 雙重下降：在相變門檻附近誤差出現峰值；過此門檻後誤差隨容量再下降，進入「收斂區」。
可證偽聲稱 B：雙重下降峰值位置可由「數據約束數 vs 連續自由度數」的相變理論預測；相同任務下，淺網峰值處誤差顯著高於深網。
主管解讀

「模型越大越聰明」是錯的時機判斷。在門檻前堆參數，每元預算的邊際產出可能是負的；過了門檻才進入正報酬。簽核前先問供應商：「這任務目前的容量落在門檻哪一側？」答不出來的，通常沒測過。

三、深網為什麼能自學規則：你買的不是算力，是「隱含偏置」

語言學大師 Chomsky 有個著名論點：孩子不可能只從有限語料就學會生成文法，所以「學規則」一定有先天內建。Wyart 在合成文法世界做了反例實驗：

  • 用上下文無關文法生成句子，句數隨長度 D 指數成長。
  • 淺網學：正如 Chomsky 所憂，只會背誦，遇新句子就垮。
  • 深網學：架構本身的強烈偏好（隱含偏置）會自動建出階層變數，用僅多項式量級的句子就學會「創造」從未出現但合規的句子。

結論：深網的架構已替你「做了一半的先天工作」。但 Wyart 謹慎補充——這不表示大腦就是深網，也不否定大腦用少 10 萬倍資料，那反而暗示大腦另有更聰明的機制。

可證偽聲稱 C：固定 CFG 合成任務上，深網達成「生成合規新句」所需樣本數隨句長 D 呈多項式成長；淺網需指數成長或學不會。
主管解讀

「模型會自己學規則」這句話，只在「深網 + 有結構的資料」同時成立。如果你要解決的問題本質是規則性的（報表對帳、流程合規、異常判讀），深網的性價比極高；如果是純隨機雜訊，再深的網也救不了——錢該花在「把問題結構化」，不是無腦堆模型。

四、預測潛空間更省錢：同樣效果，樣本少一大截

觀察：人腦學語言用的資料遠少於機器。Wyart 團隊約一個月齡的新論文主張——讓模型預測「抽象後的表徵」比預測原始 token 省樣本得多。

機制（以「街道」為例）：下一 token / 擴散模型要從「像素」去建「街道」概念，但抽象概念和底層像素的相關性極弱又雜訊大，需要海量資料才測得出信號。反之，若模型先懂「房子、汽車」等中層概念，再去建「街道」時只需預測「附近有房子概念」——概念間相關性強、信號雜訊比高，所需資料大降。

圖 3 · 三種學習目標的樣本複雜度：自省式（潛空間）預測借「已建立的鄰近概念」大幅降低所需資料量。
可證偽聲稱 D：同樣合成階層任務上，預測「教師網路潛表徵」（如 Barlow Twins / JEPA 學生—教師設定）達同等抽象品質，所需樣本數顯著少於 token 級重建，差距隨抽象層級升高而拉大。
主管解讀

這是「用對方法省大錢」的關鍵槓桿。同樣要模型懂你的產業，與其餵它原始流水（貴、慢、雜訊大），不如先教它中層概念（你的品項、流程節點、異常型態），再讓它往上組合——樣本需求可能差一個數量級。但注意：此聲稱尚在實證階段，大規模自然數據回測未完。

五、縮放定律：堆錢買算力的回報，是可被預測的

業界早發現：模型表現隨數據量、參數量、算力平滑改善，於是大家瘋狂堆算力蓋資料中心。但「改善的曲線長什麼樣、斜率多少」長期沒有解釋。Wyart 團隊提出：只需測自然語言的兩個指數就能推導訓練曲線。

  • 指數 α：詞之間相關性隨距離 n 冪律衰減 ~ n^{-α}（取決於語言）。
  • 指數 β：看過 n 個 token 後剩餘不確定性（熵）也冪律衰減 ~ n^{-β}（可從 LLM 實際行為測得，是關鍵新量）。

兩者組合即給出損失曲線指數，還能預測損失如何依「上下文長度 × 數據量」彎曲——這個二變數形狀也被他們實驗觀測到。

\[ \text{相關性}(n)\sim n^{-\alpha},\qquad \text{剩餘熵}(n)\sim n^{-\beta}\quad\xrightarrow{\ \text{組合}\ }\quad \text{Loss}\sim f(\text{data},\text{context})\ \text{冪律指數} \]
圖 4 · 縮放定律雙指數機制：相關性與剩餘熵的冪律衰減，合併推導出損失曲線。Wyart 在學術尺度（~10^9 參數/token）驗證，約對應 2–3 句上下文。
可證偽聲稱 E：對任意自然語言，測得 (α,β) 後可精確預測該語言上 LLM 訓練損失對「數據量 × 上下文長度」的二變數依賴；跨語言 α,β 差異應能解釋跨語言縮放曲線差異。
主管解讀

「再多給一倍預算，表現會好多少」是可以算的，不是玄學。要求供應商把「追加預算 → 預期表現提升」畫成一條曲線，而不是講願景。若曲線已進入平坦段，再加碼就是買熱。

六、混合成本與可合算維度（主管重點）

前面五節解釋了「模型為什麼貴、什麼時候貴得有道理」。這一節把它翻成你簽核時真正該算的帳——混合成本（blended cost）與可合算維度（computable dimension）。

6.1 混合成本：別只看「每張圖 / 每千 token」的牌價

供應商給你的單價（API 每千 token、GPU 每小時）只是直接成本。一筆 AI 專案的混合成本是所有花費攤在一起後的真實單位成本，至少含四塊：

成本塊內容常被忽略的原因
① 推論成本API 調用 / GPU 工時（供應商牌價）最顯眼，所以大家只盯這塊
② 數據與標註成本清洗、結構化、領域標註的人月常算在「既有人力」裡被隱形化
③ 驗證與對帳成本確認模型沒亂答、結果可查證的稽核流程出事才發現沒編預算
④ 失敗與返工成本模型在「卡住區」產出的廢結果、人工救火散落在各部門工時，無人歸總
\[ \text{混合單位成本}=\frac{\text{①}+\text{②}+\text{③}+\text{④}}{\text{有效產出量}} \]

關鍵洞見：如果問題落在「卡住區」（見第二節），④會爆炸性膨脹——模型答得看似合理其實錯，你還得養一批人盯著、救火、重做。這時牌價再便宜，混合成本也可能高到不如不做。反之，問題在「暢通區」且結構清楚，④趨近零，混合成本才真的低。

6.2 可合算維度：先判斷「這問題到底幾維」

「可合算維度」是我們借 Wyart 框架給主管的一把尺：這個問題的有效維度，落在指數爆炸區，還是多項式可解區？

  • 低可合算維度（多項式可解）：問題有清晰階層與規則——例：報表對帳、合規檢查、固定流程異常偵測、把既有的 SOP 自動化。這類用深網 + 你的結構化資料，樣本需求是 poly(D)，混合成本低、回報可預測。
  • 高可合算維度（指數爆炸）：問題本質是開放式、無結構、需世界級常識與互動——例：從零發明新商業模式、跨領域策略推演。這類樣本需求趨近 exp(D)，純堆模型不會自動解決，混合成本難以收斂。
圖 5 · 可合算維度：問題有效維度決定所需資源曲線形狀；落在多項式區才能談「划算」。

6.3 決策矩陣：什麼時候該花、什麼時候別花

你的問題可合算維度落在相變哪一側混合成本預期主管動作
報表對帳 / 合規 / 固定流程自動化低（有結構）暢通區低且可預測值得投，用深網 + 你的資料
客服問答 / 文件摘要（領域明確）中接近門檻中，看標註品質可投，但先小規模驗證④不爆

OODAV 的方法論錨點：我們對每一筆 AI 交付，都先幫你判斷「這問題落在哪個維度、哪一側相變」，再決定預算形狀——而不是先答應做、再做不出來。這正是「可親手驗證、不黑箱」的工程紀律在成本面的體現。
可證偽聲稱 F（成本維度）：對同一產業任務，若先用「中層概念結構化」（降低可合算維度）再上模型，其混合單位成本（含④返工）應顯著低於直接餵原始資料；且在「暢通區」任務上，追加預算的邊際表現提升應可被雙指數縮放定律（聲稱 E）預測，而非無法解釋的跳變。

八、給主管的三個簽核反向提問

反向提問 ①（維度判斷）：在簽這筆預算前，供應商能否明確回答「我的問題有效維度落在多項式區還是指數區、目前模型容量在相變門檻哪一側」？答不出來的，等於還沒做可行性分析就來要錢——這筆該擋下。

反向提問 ②（混合成本歸總）：報價單上的「每千 token / 每小時」只是①。我們有沒有把②數據標註、③驗證對帳、④失敗返工也攤進同一張表，算出真實混合單位成本？若④在卡住區爆炸，牌價再便宜也可能是冤枉錢。

反向提問 ③（邊際回報可預測性）：當我們說「再加一倍預算表現會更好」，這個「更好」有沒有一條可被數據打臉的預測曲線（如聲稱 E 的雙指數）撐著？還只是願景式承諾？曲線若已進入平坦段，再加碼就是買熱。
