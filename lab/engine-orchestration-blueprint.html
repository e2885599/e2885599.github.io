技能管線編排 · Orchestration Blueprint

把 8 款遊戲引擎的編排智慧，借來調度我們的工具

來源靈感：一支把「同一款接球小遊戲」用 Unity / Unreal / Godot / Game Maker / Construct 3 / GDevelop / RPG Maker MZ / Scratch 八套引擎各做一遍的影片。八套引擎本質是八種「如何把物件、邏輯、事件組裝成系統」的編排哲學。我們的 tool-orchestration-pipeline 技能包已是成熟編排器，本藍圖把它與 8 引擎的組合模型對照，萃取可移植原則，並規劃三階段落地——免費引擎（Godot / GDevelop / Scratch / Construct）的無碼哲學優先挹注心力。

階段 1 · 原則

萃取 10 條可移植原則

從八套引擎歸納、對齊「免費引擎優先」的編排智慧。每條標註引擎來源、對管線的啟發、與落地建議。

P1

行為附加優於腳本掛載

把「能力」宣告式附加到物件（Construct/GDevelop 的 Behavior），而非把邏輯寫死在調度器。技能應宣告「我能處理哪些事件類型 / 我有什麼能力標籤」。

來源：Construct 3 / GDevelop · 免費引擎優先

P2

事件表優於程序式呼叫

「如果 A 碰撞 B → 加分」寫成「事件→動作」宣告表，而非 if/else 散布。調度邏輯從程序式升級為「事件→技能綁定」宣告表。

來源：Construct 3 / GDevelop / RPG Maker 事件系統

P3

積木拖拽的極簡性

Scratch 把邏輯降維到拖拉彩色積木。讓使用者 / agent 用宣告式配置組裝管線，而非寫 Python orchestrator——對齊 human-in-the-loop 非工程師也能組裝。

來源：Scratch · 免費（MIT）

P4

開源 / 免費優先

Godot / GDevelop / Scratch 全免費。編排器優先採用免費開源工具、免 key 服務（如 Pollinations），避免商業授權綁定。對齊 studio-generate 成本路由哲學。

來源：Godot / GDevelop / Scratch · 開源免費

P5

場景組合（巢狀重用）

Godot 場景樹讓複雜遊戲由小場景組合。管線應由子管線模組組合，支援巢狀 / 重用，對齊 entropy-dispatch 模組化與 tool-orchestration 子管線概念。

來源：Godot · 開源免費

P6

通用性勝於過度特化

RPG Maker 最不靈活、只適合 JRPG。編排器應保持「通用編排方法論」定位，不退化成某專案專用寫死邏輯（反例警示）。

來源：RPG Maker · 特化反例

P7

降低認知負擔

免費引擎（GDevelop/Construct/Scratch）上手極快。編排器應降低使用者認知負擔——宣告式配置 + 視覺化藍圖，而非要求人人寫 orchestrator 代碼。

來源：GDevelop / Construct 3 / Scratch · 極低學習曲線

P8

資產市集模式

Unity/Unreal/Godot/Game Maker 都有資產市集。編排器應能「從市集拉取技能/工具」並自動盤點可用性——對齊 tool-orchestration 的名實核實三態。

來源：Unity / Godot Asset Store · 市集盤查

P9

藍圖模板可複用

Unreal Blueprints 把常見模式做成預製拼圖。把常見管線模式（抓取→去重→對帳→推送）做成預製「藍圖模板」，使用者拼裝即可——對齊「先做藍圖再調配」原則。

來源：Unreal Blueprints · 視覺拼圖

P10

基礎設施隱形化

Unreal 用內建物理做掉落，執行時設施隱形。把「執行 / 沙箱 / Merkle 對帳」做成隱形基礎設施，編排者只需關注「事件→技能」，對帳/驗收自動發生。

來源：Unreal 內建物理 · 對齊 Merkle 自動續鏈
