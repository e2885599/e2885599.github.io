# 逃離鴨科夫 · 射擊遊戲設計文檔（階段一）

## 0. 規模目標（用戶核定）
- **總容量**：約 7 GB（靜態資產，經 draco 壓縮後）
- **通關流程**：約 40 小時（主線）
- **難度調勻**：中段不勸退（低流失）、終局有挑戰（Boss 尖峰）、整體可證偽參數化

## 1. 技術路線
- Blender 5.2 LTS 統一資產生產（角色骨架動畫／武器／場景模組）
- 匯出 `.glb`（glTF 2.0 + draco 幾何壓縮 + KTX2 貼圖）
- Three.js（WebGPU 後端）即時執行：核心迴圈／渲染／NPC／武器／難度
- 高斯潑濺（3DGS）作場景背景層（階段二：Blender 合成多視角或現實資料 → gsplat/nerfstudio 訓練 → 匯出整合）
- 部署 GitHub Pages（靜態站＋資產分包流送）

## 3. 難度雙軌模型（可證偽）
### 3.1 固定曲線
`progress ∈ [0,1]`（0=開局，1=通關）映射五個分量：
- `enemyDensity`：敵人密度 0.6→2.4
- `enemyDamageMul`：敵人傷害倍率 0.7→1.6
- `enemyAccuracy`：敵人命中率 0.25→0.80
- `ammoScarcity`：彈藥稀缺度 0.3→1.0
- `reactionTime`：敵人反應時間 0.90s→0.35s

曲線 = 全域 smoothstep 遞增（0.15→1.0）＋ 章內正弦波動（±0.08）＋ 終局 Boss 尖峰（progress>0.92 再 +0.25）。

### 3.2 自適應 offset
依玩家表現 `perf={kdr, hitRate, deathsPerHour}` 計算技巧分 `skill∈[0,1]`，偏移 `offset∈[-0.2,+0.2]`：
`offset = (0.5 - skill) * 0.4`
- 表現好（skill 高）→ 負偏移（降難，避免無聊）
- 表現差（skill 低）→ 正偏移（升難或減緩降難，避免放棄）

### 3.3 通關率目標（可證偽指標）
設計目標：中段（章 3–6）流失率 < 15%；最終 Boss 首通率 25–40%（有挑戰但不勸退）。
驗收：上線後以匿名通關事件回報（Merkle 對帳）統計實際通關率，與目標區間對帳。

## 4. 7GB 資產預算
| 類別 | 預算 | 來源 |
|------|------|------|
| 角色/動畫 | 1.8GB | Blender 骨架＋動作捕捉風格化 |

## 5. 武器系統規格
- 射線檢測（hitscan）為主，彈道拋物線（實彈）為輔
- 後坐力：垂直+水平回彈（隨連射累積，鬆開衰減）
- 彈匣：裝填時間／預備彈量／耗彈
- 傷害模型：部位倍率（頭/軀/肢）× 距離衰減 × 難度敵人傷害倍率

## 6. NPC 系統規格
- 行為樹（選擇器/序列/裝飾器）＋ 狀態機（巡邏/警戒/交戰/撤退/重生）
- 腳本驅動對話（JSON 劇本）＋ 可選 LLM 接線（階段二）
- 難度驅動的屬性由 `difficultyAt(progress, perf)` 注入

## 7. 驗收基準（可證偽）
1. 引擎骨架：WebGPU 啟動、FPS 控制可動、遊戲迴圈無例外（本地 Chrome 實測）
2. 難度模型：單元測試雙樣本（已知點 PASS、越界 FAIL）
3. Merkle 收據：每次發版資產清單雜湊對帳
